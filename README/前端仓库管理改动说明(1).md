# 前端仓库管理改动说明

更新时间：2026-08-20

本说明只描述前端需要调整的内容。后端接口契约以 `Qgents 接口文档v2.0.19.md` 末尾第 44 节为准。

## 一、当前已有能力

创建项目页面的 GitHub 仓库来源是二选一：

```text
绑定已有仓库 -> 可多选团队已授权仓库
自动新建仓库 -> 创建一个带 README 初始提交的仓库并绑定
```

项目详情页当前支持：

- 查看项目已绑定仓库；
- 绑定团队已授权的已有仓库；
- 查看远程分支；
- 从已有远程分支创建新分支；
- 设置 Qgents 项目默认基准分支。

一个项目可以绑定多个仓库，同一个仓库也可以复用绑定到多个项目。

## 二、新增功能：项目内新建仓库并绑定

项目详情页的“代码仓库”区域新增入口：

```text
绑定已有仓库
新建仓库并绑定
```

### 2.1 入口和权限

- 入口建议放在项目代码仓库页面的仓库列表工具栏；
- 只有后端返回的当前用户具备建仓权限时显示可用按钮；
- 当前接口契约第一版要求 `TEAM_OWNER`，项目管理员仍可绑定已有仓库；
- 非 Team Owner 不能只靠前端隐藏绕过，点击或直接请求都应由后端返回 403。

### 2.2 新建仓库弹窗

字段：

- 仓库名称：必填，最长 100 字符，按 GitHub 仓库名规则校验；
- 仓库描述：可选，最长 500 字符；
- 是否私有：默认私有；
- GitHub Installation：团队有多个 `ACTIVE` Installation 时必选；只有一个时可隐藏或默认选择；
- 项目内显示名称：可选，缺省取仓库名。

提交接口：

```http
POST /api/v1/projects/{projectId}/repositories/new
Idempotency-Key: <每次新建操作稳定且唯一的 key>
```

项目创建表单同样必须保持仓库来源互斥：`repositoryIds` 与 `newRepository` 只能提交一个。前端应在切换仓库来源时清空另一组字段，并在提交前阻止同时传值；后端也会兜底返回 `422 PROJECT_REPOSITORY_SOURCE_CONFLICT`，不会静默忽略已有仓库或新建仓库选项。

成功后：

1. 关闭弹窗；
2. 刷新项目仓库列表；
3. 展示真实 `fullName`、`defaultBranch` 和仓库链接；
4. 允许用户继续创建 `develop` 等远程分支；
5. 允许项目管理员将真实远程分支设置为当前项目默认基准分支。

## 三、必须加强的空仓库约束

### 3.1 授权仓库列表

授权仓库接口可能返回：

```json
{
  "defaultBranch": null
}
```

前端应显示：

```text
未初始化
```

不得显示成 `main`，不得使用 `main` 作为空值兜底。

### 3.2 普通绑定入口

空仓库可以展示在授权列表中，但不能提交普通绑定请求：

```text
defaultBranch 为空
-> 禁用“绑定到项目”
-> 提示“仓库尚未初始化，请先创建初始提交”
```

后端仍会兜底拒绝空仓库，前端不能只依赖按钮禁用。

### 3.3 远程分支页面

当项目绑定仓库的远程分支列表为空时：

- 不要把空列表当成包含 `main`；
- 不要让“从已有分支创建分支”按钮提交空的 `fromRef`；
- 显示“暂无远程分支/仓库未初始化”；
- 当前版本应禁用创建分支操作，直到后端提供专门初始化接口；
- 只有存在真实远程分支时，才允许选择来源分支创建新分支。

### 3.4 Testset、Dry Run、Task

当仓库没有项目默认基准分支时：

- Testset 质量门禁配置不可提交；
- Dry Run 不应默认请求 `main`；
- Task 创建不能把 `main` 作为隐式基线发送；
- 页面应提示“请先初始化仓库并设置项目默认基准分支”；
- 真实错误码和后端返回的 `defaultBranch=null` 必须保留。

## 四、默认分支展示规则

页面需要区分：

|展示项|含义|
|---|---|
|GitHub 默认|GitHub 仓库全局默认分支|
|项目默认|Qgents 当前项目使用的默认基准分支|
|Task/Workspace `baseRef`|某个任务创建时固定的实际基线|

点击“设为项目默认”只修改 Qgents 项目绑定记录，不修改 GitHub 全局默认分支，也不修改已经创建的 Workspace。

## 五、前端文件改动建议

- `src/pages/ProjectDetail/CodePage.tsx`：增加“新建仓库并绑定”入口；
- 新增项目级建仓弹窗组件：表单、Installation 选择、提交状态和错误提示；
- `src/api/github.ts`：增加项目级建仓 API；
- `src/types/github.ts`：增加请求类型，允许仓库列表 `defaultBranch` 为空；
- `RemoteBranchSection.tsx`：远程分支为空时禁用无效创建操作；
- `TeamAuthorizedReposPage.tsx`：空仓库显示“未初始化”，禁用普通绑定；
- `QualityGateConfigDrawer.tsx`：去掉空默认分支回退 `main`；
- `DryRunCreateModal.tsx`、`TaskTriggerModal.tsx`：无真实基线时阻止提交并提示原因。

## 六、验收流程

```text
创建项目
  -> 绑定已有多个仓库，或自动新建一个仓库
  -> 项目详情显示仓库列表

项目详情
  -> Team Owner 点击“新建仓库并绑定”
  -> 创建成功并自动初始化 README
  -> 列表显示真实默认分支
  -> 创建 develop 分支
  -> 设置 develop 为项目默认基准分支

空仓库
  -> 授权列表可见且显示未初始化
  -> 普通绑定按钮禁用
  -> 不回退 main
  -> 不发起无效分支、Task、Testset 或 Dry Run 请求
```
