# 二、A：平台框架与 IM 协作

## 核心目标

  实现：

> 用户进入团队和项目 → 查看项目总群/需求群 → 人和 Agent 共同讨论 → 创建需求群 → 接收群消息和通知。

## 负责页面

  对应 V3：

- `01` 登录/注册
- `02` 个人中心团队/项目切换
- `03` 团队项目中心
- `04` 创建项目与角色
- `05` 项目概览
- `06` 项目总群
- `07` 创建需求群
- `08` 需求群聊
- `21` 共享 Memory
- 新增：通知中心抽屉

## 具体任务

### 1. 平台基础框架

- 路由配置
- 登录态保持
- 项目级页面布局
- 左侧导航
- 顶部搜索与个人中心
- 团队/项目上下文
- 权限路由控制
- 403、404、空状态页面
  这里按照后端角色判断：
- `TEAM_OWNER`
- `TEAM_MEMBER`
- `PROJECT_ADMIN`
- `PROJECT_MEMBER`
  A 只负责前端显示和入口控制，真正权限以后端返回为准。

### 2. 团队与项目

- 登录、注册、退出
- 团队列表
- 项目列表
- 创建项目
- 团队/项目切换
- 当前身份展示
- 项目概览基础统计
- 无权限项目的禁用和提示

### 3. 会话列表

  左侧群聊列表实现：

- 项目总群固定在顶部
- 需求群列表
- 新建需求群
- 搜索
- 最近活跃排序
- 置顶
- 未读数量
- 最新消息摘要
- 群聊归档
- 加载更多
- 空状态
  后端接口暂时不完整的字段全部先 Mock：

### 4. 群聊主体

- 消息列表
- 文本消息
- 代码块消息
- 图片和文件消息
- 引用回复
- @成员
- @Agent
- 系统消息卡片
- 任务进度卡片
- Diff 卡片
- 交付物卡片
- 历史消息分页
- 消息发送状态
- 失败重发
- 自动滚动和新消息提示
  A 不负责真正创建任务，但点击“@Agent 发起任务”或任务卡片时，要能把用户带到 B 负责的任务流程。

### 5. 项目总群

- 公共讨论
- 项目公告
- 各需求群结构化进度卡片
- 任务完成动态
- Testset 异常动态
- MR 待处理动态
- 点击动态跳转需求群、任务或 MR

### 6. Memory

  因为 Memory 主要来源于群聊，所以交给 A：

- Memory 列表
- Memory 详情
- 从群消息生成草稿
- 手动创建草稿
- 提交审核
- 批准/拒绝
- 标签和来源消息展示

### 7. 通知中心

  先用 Mock 实现：

- 未读数量
- 任务完成
- 任务失败
- Agent 需要处理
- 交付物待验收
- MR 待处理
- 标记已读
- 全部已读
- 点击通知跳转

## A 的完成标准

  A 独立演示时必须能跑通：

> 登录 → 切换项目 → 进入项目总群 → 创建需求群 → 发送消息 → @Agent → 跳转任务创建 → 收到任务完成通知。
>   A 不是只做登录和框架，而是负责整个产品最核心的 IM 协作入口。

# 三、B：Agent 云端任务与交付闭环

## 核心目标

  实现：

> 用户从需求群派任务 → Agent 在云端后台执行 → 用户离开页面也不影响 → 查看进度、日志和产物 → 验收或退回。
>   这是平台差异化最明显的一块。

## 负责页面

  对应 V3：

- `09` 触发任务
- `10` 任务中心
- `11` 任务详情
- `12` 工作流查看
- `13` Agent 团队
- `14` 交付中心
- `20` 共享 Skill

## 具体任务

### 1. 通用请求和 Mock 基础

  B 负责搭建轻量的数据访问规范：

- API Client
- React Query 查询封装
- Query Key 规范
- Mock/真实接口切换
- SSE 通用连接管理
- SSE 断线重连
- Mock 事件时间线
  但B不需要替所有人写接口。A、B、C各自维护自己领域的：

  B只提供通用底座。

### 2. 触发任务

  从需求群进入任务弹窗：

- 任务说明
- 所属需求群
- 自动继承群聊上下文
- 选择自动/手动启动
- 选择 Testset
- 代码任务目标
- 非代码任务目标
- 提交云端运行
- 提交成功提示
  提交后必须明确显示：
  > 任务已提交至云端。你可以安全离开当前页面，Agent 会继续执行。

### 3. 任务中心

  提供两种视图：

- 状态看板
- 任务列表
  状态至少包含：
- 规划中
- 待执行
- 排队中
- 执行中
- 已暂停
- 已完成
- 已失败
- 已取消
  支持：
- 按需求群筛选
- 按状态筛选
- 按仓库筛选
- 按 Agent 筛选
- 搜索任务
- 查看运行时长
- 查看当前步骤
- 查看是否需要人工处理

### 4. 任务详情

- 任务基本信息
- 所属需求群
- 工作包
- 子任务
- Planner、Developer、Tester、Reviewer Agent 执行步骤
- 当前状态
- 执行时间
- Workspace/Sandbox 只读摘要
- 实时日志
- 运行错误
- 重试
- 暂停
- 恢复
- 取消
- 查看交付物
- 返回需求群
  目前没有真正的“等待人工输入”接口，可以先预留 Mock 状态，不阻塞本期主流程。

### 5. SSE 任务事件

  B 负责处理：

  状态更新后：

- 刷新任务卡片
- 刷新任务详情
- 更新步骤进度
- 触发 A 的通知中心
- 更新群聊中的任务卡片
  A负责消息展示，B负责任务事件和状态数据。

### 6. 工作流页面

  由于后端明确只支持系统默认工作流，本期页面做成只读：

  支持：

- 查看节点
- 查看每个节点使用的 Agent
- 查看 Skill
- 查看 Testset
- 查看运行状态
  本期不做：
- 拖拽节点
- 自定义连线
- 新建工作流
- 发布工作流
  这样可以显著降低工作量。

### 7. Agent 团队

- 系统 Agent
- 私有 Agent
- 团队共享 Agent
- Agent 身份卡
- 创建 Agent
- 编辑自己的 Agent
- 发布/取消发布
- 归档
- 能力标签
- 可用状态
- Skill 绑定

### 8. 共享 Skill

  Skill 与 Agent 强关联，所以分给 B：

- Skill 列表
- 创建草稿
- 编辑草稿
- 提交审核
- 批准/拒绝
- 发布状态
- Agent 使用情况
- 标签筛选

### 9. 交付中心

- 按需求群查看交付物
- 按工作包查看交付物
- 代码、文档、测试报告等交付类型
- 交付物详情
- 接受交付
- 拒绝并填写原因
- 交付版本
- 跳转 Diff
- 跳转 MR
- 返回需求群

## B 的完成标准

  B 独立演示时必须跑通：

> 从需求群发起任务 → 云端排队 → Agent 执行 → 查看实时步骤和日志 → 产生交付物 → 接受或退回 → 完成通知。
>   B负责的是平台的核心差异化能力，不只是一个普通任务列表。

# 四、C：GitHub 代码交付与质量门禁

## 核心目标

  实现：

> Agent 完成代码 → 查看仓库和分支 → 查看 Diff → 执行 Testset/Dry-run → CQ+1 → 创建并合并 MR。

## 负责页面

  对应 V3：

- `15` 代码与 Branch
- `16` Diff/CR
- `17` Testset/Dry-run
- `18` MR 质量门禁
- `19` 项目成员与权限
- `22` 项目设置
- GitHub 集成设置

## 具体任务

### 1. GitHub 集成

- GitHub App 安装入口
- 授权状态
- 已授权仓库
- 绑定仓库到项目
- 解除绑定
- 设置默认分支
- 仓库同步状态
- GitHub 原始链接
- 同步失败提示  
  Mock 阶段模拟：
- 已授权
- 未授权
- 授权过期
- 同步中
- 同步失败

### 2. 代码与 Branch

- 多仓库列表
- 分支列表
- main/默认分支
- 保护分支
- 工作分支
- 关联任务
- 关联需求群
- 提交数量
- Diff 统计
- MR 状态
- Testset 状态
- 分支详情抽屉
- 创建 MR 入口
  前端不直接创建、推送或修改 Git 分支，只展示后端受控执行结果。

### 3. Diff 与 CR

- 文件树
- 新增、修改、删除状态
- 行级 Diff
- 变更统计
- 文件分页
- 二进制文件提示
- 行级评论
- 普通评论
- 评论定位
- 提交 SHA
- 引用 Diff 回需求群
- 跳转关联任务和交付物
  本期没有 Reviewer 指派设计，因此不做：
- 指定 Reviewer
- Reviewer 管理
- Reviewer 权限切换

### 4. Testset 与 Dry-run

- Testset 列表
- 创建和修改 Testset
- 启用/停用
- 仓库关联
- 命令和超时时间
- 运行测试
- 测试状态
- 测试用例摘要
- Dry-run 发起
- 冲突结果
- 测试报告
- 历史运行记录
  后端缺少历史列表接口时，先 Mock。

### 5. MR 与质量门禁

- MR 列表
- MR 详情
- 从已接受交付物创建 MR
- GitHub PR 编号和链接
- 同步 GitHub 状态
- Testset 检查
- AI Review
- Dry-run
- CQ+1
- CQ 拒绝和修改意见
- 门禁汇总
- 合并按钮
- 合并失败原因
  按当前后端文档：
- 非作者的项目成员可以提交 CQ+1
- `PROJECT_ADMIN` 才能最终合并
- 不增加 Reviewer 指派流程

### 6. 项目成员与权限

- 项目成员列表
- 添加团队成员到项目
- 移除项目成员
- `PROJECT_ADMIN`/`PROJECT_MEMBER` 调整
- 当前用户权限显示
- 权限不足状态
- 最后一名 Project Admin 保护

### 7. 项目设置

- 项目资料
- 仓库绑定
- 默认分支
- Branch Policy
- Quality Gate
- 必选 Testset
- CQ+1 配置
- 直接推送限制
- 项目归档与恢复

## C 的完成标准

  C 独立演示时必须跑通：

> 查看 Agent 产生的代码分支 → 打开 Diff → 添加 Comment → 执行 Testset 和 Dry-run → CQ+1 → 创建/同步 MR → Project Admin 合并。
>   C不是只做设置页，而是负责完整代码交付主链路，技术含量与业务价值都足够。
